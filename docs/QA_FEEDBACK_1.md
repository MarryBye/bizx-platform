## 1. Відповіді на уточнення та погоджені рішення

### ❓ Питання 1: Що таке `users.preferredLanguage`? Чи є це в БД зараз?
- **Відповідь:** Ні, зараз у базі даних цієї колонки **немає**. Це була пропозиція на майбутнє для синхронізації мови між різними пристроями одного облікового запису.
- **Погоджене рішення для поточної задачі:** Для старту ми **не чіпаємо базу даних і не створюємо зайвих міграцій**. Зберігаємо мову виключно локально:
  - У браузері (Web): `localStorage.setItem('bizx_locale', 'ua' | 'en')`.
  - У мобільному додатку (Mobile): `AsyncStorage.setItem('bizx_locale', 'ua' | 'en')`.
  - Це працює блискавично, надійно і не потребує змін у backend API. Колонку в БД додамо згодом за бажанням.

### ❓ Питання 2: Як саме працює `setLocale` та реактивний хук `t('key')`?
- **Відповідь:** Так, саме так, як ви описали:
  1. Користувач натискає кнопку (наприклад, перемикач `UA` / `EN` або прапорець).
  2. Викликається `setLocale('en')`.
  3. Всередині хука `setLocale`:
     - Оновлюється реактивний React Context (`locale = 'en'`).
     - Записується значення в `localStorage` (щоб при оновленні сторінки F5 мова залишилася англійською).
  4. Завдяки React Context усі компоненти на сторінці **миттєво перемальовуються без перезавантаження сторінки**.
  5. Функція `t(key)` тепер бере переклад зі словника `en.ts` замість `ua.ts`.

## 2. План виправлень (Формат: Причина — Рішення)

### Завдання 1: Прев'ю та завантаження медіа магазину

- **Причина:**
  1. API повертає відносний шлях `/storage/file/stores/...`.
  2. У Vite dev-сервері (`:3102`) не було налаштовано `proxy` на NestJS (`:4000`), тому браузер отримував 404 при запиті на `localhost:3102/storage/...`.
  3. При виборі файлу в `<input type="file">` не створювався локальний blob URL (`URL.createObjectURL(file)`).
  4. Відсутній `onError` fallback для тегу `<img>`.
- **Рішення:**
  1. Додати proxy для `/storage` та `/api` у `apps/bizx-admin/vite.config.ts`.
  2. Створити утиліту `resolveMediaUrl(url)` (додає базовий URL API, якщо шлях відносний).
  3. У `StoreSettingsView` реалізувати миттєве локальне прев'ю при виборі файлу до завантаження на сервер.
  4. Створити компонент `StoreMediaImage` з автоматичним перемиканням на `StorePlaceholder` / `BannerPlaceholder` при помилці завантаження.

---

### Завдання 2: Мінімалістичні повідомлення про помилки з кодами для dev

- **Причина:**
  - У `useAuthStore.ts` було захардкоджене довге пояснення про ролі клієнтів та адміністраторів платформи.
  - Помилки з бекенда виводилися у сирому вигляді без чіткого коду помилки.
- **Рішення:**
  1. Створити реєстр кодів помилок платформи у `packages/common-types` (наприклад, `AUTH_INVALID_CREDENTIALS` [#AUTH_1001], `AUTH_FORBIDDEN_PORTAL` [#AUTH_1002]).
  2. У UI відображати лише 1 лаконічний рядок:  
     *Приклад:* `Невірний логін або пароль [AUTH_1001]`  
     *Приклад:* `Доступ до бізнес-порталу обмежено [AUTH_1002]`
  3. Розширений стек та технічні деталі виводити лише в консоль розробника.

---

### Завдання 3: Власний модуль перекладів (i18n) без зайвих бібліотек

- **Причина:**
  - У проєкті відсутня інтернаціоналізація. Тексти захардкоджені, немає механізму вибору мови.
- **Рішення:**
  1. Створити власний легковажний модуль перекладів у `packages/i18n` (або `packages/utils/src/i18n`):
     - **Словники:** `ua.ts` (базовий) та `en.ts`.
     - **Типізація:** `type TranslationKey = NestedKeyOf<typeof ua>` — забезпечує **100% автокомпліт у редакторі коду** та захист від одруківок у ключах під час білду.
     - **Провайдер та хук:** `I18nProvider` та `useTranslation()`.
     - **Збереження:** `localStorage` (Web) / `AsyncStorage` (Mobile).
     - **Автовизначення:** якщо сховище пусте — перевіряти `navigator.language` (якщо `uk`/`ua` -> `ua`, інакше `en`), дефолт платформи `ua`.
     - **Підтримка інтерполяції:** `t('store.items_count', { count: 5 })`.
  2. Додати перемикач мови `UA | EN` у хедер/сайдбар адмінки та в налаштування мобільного додатку.

---

### Завдання 4: Відображення аватарки користувача

- **Причина:**
  1. В адмінці шлях `/storage/file/avatars/...` не резолвився через відсутність домену бекенда у відносному URL.
  2. У мобільному додатку компонент `<Image source={{ uri }} />` не підтримує SVG-файли та відносні шляхи.
  3. У `seed.ts` генерувався примітивний SVG-круг, який без масок відображався як суцільний синій круг.
- **Рішення:**
  1. Нормалізувати URL через `resolveMediaUrl(avatarUrl)`.
  2. Створити компонент `UserAvatar` (окремо адаптований під Web та Mobile):
     - Якщо аватарка є і завантажилася — показувати картинку.
     - Якщо сталася помилка завантаження або аватарки немає — показувати привабливий круг з **ініціалами імені** користувача (наприклад, **ТШ** для Тараса Шевчука, **АК** для Олександра Коваленка) на фоні брендового кольору.

## 3. Рекомендації сервісів для трекінгу завдань

Якщо потрібно перенести управління задачами та багами зі звичайних `.md` файлів у зручний професійний інструмент, ось найкращі варіанти:

### 🥇 1. Linear (Free Plan) — **(Найкращий вибір)**
- **Сайт:** [linear.app](https://linear.app)
- **Умови:** Повністю **безкоштовний** для невеликих команд (до 250 активних тасок, необмежена кількість користувачів).
- **Плюси:**
  - Найшвидший та найестетичніший інтерфейс у світі розробки (гарячі клавіші, темна тема).
  - Ідеальна інтеграція з GitHub: гілки та Pull Request автоматично прив'язуються до тасок (наприклад, гілка `fix-mobile-button-BIZ-12` автоматично пересуває таску в "In Progress", а мердж PR автоматично її закриває).
  - Підтримка циклів (спринтів), roadmap та пріоритетів.

### 🥈 2. GitHub Projects / Issues — **(100% безкоштовно без будь-яких лімітів)**
- **Де знаходиться:** Прямо у вашому репозиторії: `https://github.com/MarryBye/bizx-platform/projects`
- **Умови:** Повністю **безкоштовно**, без лімітів на кількість задач чи учасників.
- **Плюси:**
  - Не треба реєструватися в інших сервісах — все знаходиться всередині вашого GitHub.
  - Зручні Kanban-дошки (Backlog, Todo, In Progress, Done).
  - Коли в коміті або PR пишеться `Fixes #12`, GitHub автоматично закриває задачу.

### 🥉 3. Plane.so — **(Open-Source альтернатива Linear)**
- **Сайт:** [plane.so](https://plane.so)
- **Умови:** Є безкоштовна Cloud-версія, або можна безкоштовно підняти в Docker на власному сервері.
- **Плюси:**
  - Візуальний клон Linear, але з відкритим кодом.
  - Повний контроль над даними, якщо запускати self-hosted.
